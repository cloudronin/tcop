# Amendment 003 implementation issues

Items 1-13 record Phase 0 findings and planned resolutions. Item 14 records the Phase 1 owner decisions. The build map records which foundations are implemented. No spec is edited. Third-party citation roots are defined in amendment-003-admission-notes.md.

1. **Arm-name collision.** Problem: the base conditions already use E0/E1/E2. Amendment 001 keeps them; amendment 003 reuses the names for different deployment choices. Evidence: `benchmark/studies/external-warning-adaptive-crosshost-v1.yaml:23,38,43`; `spec/external-warning-adaptive-crosshost-amendment-001.md:12`; amendment 003:21-30. Resolution for code: put ladder arms only under `enforcement_ladder`. Use an explicit namespace in records, for example `study_axis=enforcement_ladder, arm=E0`. Never inject ladder entries into `conditions` or either `required_conditions` list. Existing base E0/E1/E2 strings stay unchanged. The validator must check semantics and exact legacy lists, not blindly ban those strings.

2. **Pairing under live sampling.** Problem: paired does not mean identical action traces across independently sampled live arms. A1-A4 depend on each arm's denial. Evidence: amendment 003:93-98; amendment 002:13-21. Resolution for code: pair by `(family, role_script, timing_cell, seed)`. Freeze each arm's live episode and strict-replay it in that arm. Retain separate trace and outcome digests. Compare all outcome fields to that arm's live record. Disagreement is `environment_failure`. Never force the E0 trace into E1/E2. Report the pairing unit and live sampling variation.

3. **Zero damage denominator.** Problem: E0 can execute zero harmful actions; damage prevented is then undefined, including 0/0. Evidence: amendment 003:121-123. Resolution for code: emit `undefined` with raw numerator and zero denominator. Keep the point in the output and disclose why it cannot be plotted as a numeric ratio. Never drop it or impute zero/one. Do not serialize NaN; `src/tcop/canonical.py:14-26` rejects it.

4. **Draft public-source mapping.** Problem: S-A/S-B/S-C are named but their reduced reconstruction needs clause-level public-source mapping. `docs/case-hugging-face.md` is absent in this checkout. Evidence: amendment 003:72-91,152-154. Resolution for code: scripts keep `draft-pending-mapping` until that file exists and supports each script's harmful intent, A0, and representable adaptations. Drafts can be sealed and censused. Every non-smoke admission rejects draft status. No real incident efficacy claim follows from a synthetic reconstruction.

5. **Smoke status.** Problem: a single-host smoke run produces frontier-shaped numbers, while BLOCKED artifacts must contain no efficacy findings. Evidence: v1:8-12,21-24; amendment 003:52-59,125-138; `src/tcop/external_adaptive_crosshost.py:93,97-115`. Resolution for code, decided: seal smoke as `SMOKE_INVALID_FOR_RESULTS`, `valid_for_results: false`. It must never be BLOCKED-shaped. Verify can accept it only as a well-formed smoke artifact and returns that explicit status. Every result, report, and paper-extraction path refuses smoke. Smoke numbers never enter efficacy tables. A failure before smoke execution may still seal BLOCKED with no numbers.

6. **Unknown manifest versions pass verification.** Problem: hash checks only recognize 1.1 and 1.2; another version can pass with BLOCKED plus a matching root. Evidence: `src/tcop/external_adaptive_crosshost.py:97-112`. Resolution for code: explicit supported-version dispatch, including 1.3 requiring amendments 001/002/003. Unknown versions raise `TCOPCommandError`. Recompute plan hash, amendment hashes, canonical sidecars, effective manifest, source roots, and status-specific gates. A self-consistent root alone is not semantic validation. Keep known legacy blocked artifacts verifiable without rewriting them.

7. **Runtime cannot support all four actions as written.** Problem: endpoint removal is native, but the pinned policy API has no named credential-scope revocation, freeze, or forensic snapshot action. Evidence: `openshell/proto/openshell.proto:1957-2038`; `openshell/proto/sandbox.proto:96-104,186-196`. StopSandbox is separate lifecycle control (proto:110-125); status snapshots (proto:1343-1384) are not forensic snapshots. Resolution for code: explicit capability admission rejects unsupported actions. Do not substitute provider detach, destination removal, stop/delete, or in-sandbox commands. The full deliverable and S-C scope-revocation admission are blocked until the study owner resolves this runtime/spec mismatch. Returning a local unsupported rejection is not evidence that OpenShell received a tightening request.

8. **Native approval is not a removal-approval setting.** Problem: draft approvals merge added rules. Auto mode is conditional on prover findings, not blanket tightening acceptance. Evidence: `openshell/crates/openshell-server/src/grpc/policy.rs:1209-1240,1433-1499,6547-6575`; `openshell/proto/openshell.proto:2500-2582`. Resolution for code: record submission route and effective approval settings separately from E2a/E2b labels. Do not mislabel direct UpdateConfig as draft-approved. A harness human gate can review an exact candidate hash but does not satisfy the native-setting wording by itself. Investigate the native UpdateConfig interceptor hook (`openshell/crates/openshell-gateway-interceptors/src/routes.rs:35`; `openshell/proto/gateway_interceptor.proto:67-90,118-129`) for an actual packaged approval service and its timeout/review semantics. The hook alone is not a human approval workflow. Keep native E2b admission blocked pending an explicit supported interpretation. E2a/E2b records are never pooled.

9. **Base file is not the default effective installed policy.** Problem: the base YAML says default, but onboarding defaults to balanced and adds agent presets. Evidence: `nemoclaw/nemoclaw-blueprint/policies/openclaw-sandbox.yaml:4-14`; `nemoclaw/src/lib/onboard/policy-selection-prompts.ts:150-163`; `nemoclaw/nemoclaw-blueprint/policies/tiers.yaml:23-32`; `nemoclaw/src/lib/onboard/policy-tier-suppression.ts:38-43`. Resolution for code: pin the selected tier, each preset hash, provider/global overlays, and actual installed effective policy bytes. E1/E2 must share these. Do not use the base source hash as installed-policy evidence. Do not choose restricted silently to get a cleaner result. No installed-policy hash exists after a license-gated install.

10. **A4 and the E0 frontier anchor conflict.** Problem: A4 runs after a harmful denial, while E0 is claimed to anchor bottom right. With no E0 denial, A4 can be not_triggered and useful-work completed can be zero or undefined. Adaptive harmful attempts can also differ, so counting every non-executed conditional branch as prevented can inflate the ratio above its E0 denominator. Evidence: amendment 002:13-21; plan YAML:25-29; amendment 003:121-131. Resolution for code: retain branch disposition and raw planned, triggered, attempted, executed, denied counts with stable action IDs. Do not count not_triggered/not_representable as prevented, do not force E0 to (1,0), and do not silently change A4's trigger. Flag the anchor/accounting conflict for owner resolution before a results run. Explicitly define which harmful opportunity set is compared to E0 before sealing the prediction. This is a remaining scientific-contract decision, not permission to invent an estimator.

11. **Policy submission is not policy enforcement.** Problem: duplicate calls can reuse a revision, drafts approved in a batch share a revision, superseded changes never load, and CLI polling is coarse relative to the grid. Evidence: `openshell/crates/openshell-server/src/grpc/policy.rs:3720-3770`; `openshell/proto/openshell.proto:2056-2139,2560-2582`; `openshell/crates/openshell-cli/src/run.rs:6200-6256`. Resolution for code: serialize requests to the bound sandbox; retain base/candidate hashes, request identity, returned version, active version, and raw statuses. Use an explicit deadline. LOADED becomes accepted; FAILED and pre-load SUPERSEDED become rejected; PENDING beyond deadline becomes timed_out. Retain late loads. Measure policy and denial events at source, not from CLI exit time. Guard effective/global/provider authority and stale writes. Do not claim that each submitted invocation creates a new revision.

Resolution for code: validate immutable locks and content manifests against plan pins, verify owner-supplied host attestations with machine/administration identity, and reject aliases, two processes, or two containers on one host. Names alone never establish topology. Make all admission blockers explicit. Synthetic single-host work stays smoke only.
