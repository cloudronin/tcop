# TCOP/TCF v0.1 Deterministic Benchmark Report

**Run date:** 2026-07-31  
**Profile:** deterministic synthetic reference implementation  
**Command:** `make verify`  
**Result:** 32 tests passed; 50 benchmark runs completed; same-seed artifact digest reproduced exactly.

## Executive result

The v0.1 reference implementation proves its intended *mechanism* under a
controlled simulator: signed observations can be disseminated to five local
trust nodes, validated, locally resolved into capability restrictions, and
recorded in separately auditable protocol, resolution, evidence, and benchmark
ground-truth streams.

For the two immediate cross-domain compromise cases, TCX prevented downstream
material exposure where no-runtime, policy-only, local-only, and the current
minimal central-monitor control did not. TCX did **not** prevent exposure where
critical context arrived after the scheduled actions or where partitions
isolated the receiving nodes. A single valid but malicious observer also caused
a false local constraint, although it could not force quarantine. Those negative
cases are desired findings: they establish where the v0.1 architecture has a
known boundary rather than presenting a universal trust claim.

These are deterministic, scenario-authored regression results—not evidence of
real-world security efficacy or comparative performance of live AI agents.

## What was run

The run exercised ten scenarios (B-001–B-010) against five configurations:

1. `no_runtime_defense`
2. `policy_only`
3. `local_only`
4. `central_monitor`
5. `tcx`

The simulator uses a virtual clock, deterministic Ed25519 fixture keys, static
authority discovery, fixed propagation graph, and a seeded workload. There are
no external model calls, live networks, background services, or wall-clock
dependencies. Each run writes a manifest, JSONL protocol/resolution/truth
streams, accepted evidence in JSONL and SQLite, propagation graph, metrics,
summary, and result digest.

## Interpretation

### Confirmed mechanism behavior

- **B-002 and B-003:** TCX delivered evidence to every trust node before the
  two scheduled downstream interactions. Every receiving node issued a local
  capability constraint, so cross-domain blast radius was zero. Local-only and
  central-monitor controls constrained only `node-1`; the independently
  governed downstream nodes remained exposed.
- **B-005, B-006, and B-009:** the receiver rejected unknown identities,
  duplicate/replayed delivery, and future timestamps respectively. No synthetic
  downstream effect occurred.
- **B-010:** two critical reports from observers in the same trust domain did
  not count as independent corroboration. They caused only the reference
  resolver's reversible constrained state, not quarantine.
- **Reproducibility:** repeated B-002/TCX runs with seed 42 produced identical
  SHA-256 result digests over protocol, resolution, truth, propagation, and
  metric records.

### Deliberate failure cases

- **B-007 delayed evidence:** context arrived at virtual time +10, after the
  scheduled downstream interactions at +0 and +1. TCX observed and constrained
  later, but recorded ASR 1.0 and CBR 2. This differentiates sensor/delivery
  delay from trust-resolution latency.
- **B-008 partition:** `node-4` and `node-5` were partitioned from the source.
  Context dissemination was 0.6 (three of five nodes); both receiving domains
  experienced material exposure. TCX therefore does not claim global coverage
  under a partition.
- **B-004 false accusation:** one signed critical observation triggered a
  reversible local constraint for a benign subject, producing false-containment
  rate 1.0 for that scenario. It did not produce a global quarantine. This is a
  priority calibration issue for the reference resolver, not a pass condition.

## Implementation evidence

- The conformance suite covers CT-001–CT-020, canonicalization, an authority
  cycle, signed golden fixture compatibility, and the deterministic workload
  adapter.
- The benchmark has three isolated streams: `protocol-events.jsonl`,
  `resolution-events.jsonl`, and `benchmark-truth.jsonl`. The core protocol,
  resolver, and responses do not import benchmark-truth logic.
- `propagation-graph.json` labels external workflow effects independently of the
  protocol. Constraints can block future scheduled edges but cannot relabel
  earlier effects.
- Continuous integration and a deterministic Docker Compose entry point are
  included. The Compose configuration was validated; the benchmark itself was
  executed locally through `make verify`.

## Recommended next deterministic work

1. Replace the single-observer constraint rule with profile-configurable
   thresholds, then add a false-containment recovery scenario and calibration
   sweep.
2. Add deterministic authority-delegation fixtures, withdrawal/supersession,
   evidence-access failure, and explicit synchronization-after-heal scenarios.
3. Expand each B scenario from the current two-edge graph into topology and
   risk-profile parameter sets; retain fixed seeds and virtual time.
4. Implement a deterministic policy-engine adapter and a real central-monitor
   baseline before claiming those comparisons are representative.
5. Add a containerized CI run when the build environment is available; do not
   introduce live LLMs or adaptive attacks into the baseline.
