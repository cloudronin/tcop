# TCOP/TCF deterministic experiment results — second iteration

## Bottom line

The deterministic mechanism is validated as a reproducible reference model.
TCOP’s comparative superiority over a well-built centralized system is **not**
validated. The expanded controls show a narrower, useful result: authenticated
cross-domain context plus local response can contain propagation when it arrives
before the relevant harmful action; it cannot protect a domain that has not
received the context.

All work in this iteration remains deterministic: virtual time, deterministic
keys, fixed rules, in-process faulting transport, and simulated response
adapters. No LLM, production enforcement, external network, Kubernetes, or
randomized workload is involved.

## Reproduction

Run the complete suite with:

```bash
make research
```

The completed run passed the TCX schema check and all 36 tests. It performed 70
benchmark runs (B-001 through B-010 across seven baselines), reproduced the
same-seed digest, and retained oracle isolation. Raw benchmark artifacts are
written to `artifacts/verify/`; timing, topology, posture, and ablation records
are written to `artifacts/experiments/`.

## Comparable baseline result

The suite now separates the limited historical central monitor from
`central_equal`: the latter receives the same observations as its central node
and broadcasts the same resulting envelope to every domain. It is an
upper-bound control with global enforcement reach, not a TCOP implementation
and not a model of local sovereignty.

| Condition | Central equal | TCX | Interpretation |
| --- | ---: | ---: | --- |
| B-002 indirect injection | objective 0 / CBR 0 | objective 0 / CBR 0 | Both contain the normal case. |
| B-003 memory poisoning | objective 0 / CBR 0 | objective 0 / CBR 0 | Both contain the normal case. |
| B-007 delayed evidence | objective 1 / CBR 2 | objective 1 / CBR 2 | Evidence arrives after the modeled harm. |
| B-008 partition | objective 0 / CBR 0 | objective 1 / CBR 2 | `central_equal` assumes global reach; TCX cannot act at the two unreachable domains. |

`objective` is scenario-specific attacker success, and CBR is cross-domain
blast radius. The B-008 comparison does **not** establish that a real central
system is superior: it only demonstrates the advantage of the deliberately
assumed global control channel. Conversely, the normal-operation ties do not
establish TCX superiority. A future central implementation must use an explicit
fault model and the same reachable enforcement paths before it is a fair
architecture comparison.

The explicit architecture controls make the same limitation visible. For B-002,
TCX and `central_equal` both have attack objective 0 and CBR 0; a modeled
unavailable central service has objective 1 and CBR 2. A malicious central
authority with global reach is recorded as a threat-model control that can force
false containment and quarantine in all five domains. That last control is a
modeled consequence, not evidence from a production central implementation.

## Objective-specific metrics

Attack success is no longer one overloaded number. B-004 measures
false-containment success and B-010 measures availability-disruption success;
the remaining attack scenarios measure compromise propagation. The aggregate
`mean objective success` field is retained only for regression tracking and
must not be read as a common ASR.

| Baseline | Propagation success | False-containment success | Availability-disruption success | Mean CBR |
| --- | ---: | ---: | ---: | ---: |
| No runtime defense | 0.444 | 0.000 | 0.000 | 0.889 |
| Dynamic local policy | 0.444 | 0.111 | 0.111 | 0.889 |
| Local only | 0.444 | 0.111 | 0.111 | 0.889 |
| Central limited | 0.444 | 0.111 | 0.111 | 0.889 |
| Central equal | 0.111 | 0.111 | 0.111 | 0.222 |
| TCX | 0.222 | 0.111 | 0.111 | 0.444 |

This explains why the original aggregate comparison could mislead. TCX reduces
propagation and blast radius relative to no defense, while signed but false
observations can still impose a narrow restriction. Authentication proves who
made a claim; it does not make the claim true.

## Containment-window sweep

The timing experiment has 108 cases. It varies observation delay (0, 1, 3),
per-hop dissemination delay (0, 1, 3), resolution delay (0, 1), enforcement
delay (0, 1), and attack propagation interval (1, 3, 5) in a five-domain chain.
It fully contains 52 of 108 cases (48.1%).

For each scheduled harmful interaction, the experiment calculates:

```text
action time − effective restriction time at that receiving domain
```

The containment window is the minimum of those values. It is non-negative in
exactly the full-containment cases. This is the correct operational version of
the relation: observation, validation, dissemination, resolution, and
enforcement must complete before the next relevant harmful action at its target.

## Topology sweep

The topology experiment covers 3, 5, 10, and 20 domains; chain, star, mesh, and
hub overlays; and propagation intervals of 1, 3, and 5 virtual ticks. It uses a
fixed two-tick overlay-hop delay and a two-tick preparation period before the
first downstream action. It fully contains 45 of 48 cases (93.8%).

| Overlay | Full containment |
| --- | ---: |
| Chain | 9 / 12 |
| Star | 12 / 12 |
| Mesh | 12 / 12 |
| Hub | 12 / 12 |

The three misses are the fast-propagating multi-domain chain cases: context
cannot reach later nodes before their scheduled actions. This is a topology and
timing result, not a throughput or real-network scaling claim; the transport is
still an in-process deterministic model.

## Partition operating postures

With nodes 4 and 5 unable to receive current context, the posture profile makes
the security/utility trade-off explicit. Weights in this calibration are 0.1
for public search and 1.0 for financial transfer. Security loss is allowed
harmful capability weight; utility loss is blocked benign-workload weight.

| Posture | Security loss | Utility loss | Public search | Financial transfer |
| --- | ---: | ---: | --- | --- |
| Fail open | 1.10 | 0.00 | available | available |
| Fail constrained | 0.10 | 1.00 | available | blocked |
| Fail closed | 0.00 | 1.10 | blocked | blocked |
| Risk-sensitive | 0.10 | 1.00 | available | blocked |

There is no universally correct posture. This result makes the policy choice
auditable instead of treating a partition as an undefined protocol failure.

## False containment and recovery

A single valid but malicious critical observation constrains the benign
subject's `data.export` capability. In the calibration it yields benign task
completion 0.0 and normalized severity-weighted utility loss 1.0. It does not
force quarantine. After five virtual ticks, a signed `recovery.withdrawal`
referencing the observation restores the local envelope without human
intervention. Evidence remains immutable; withdrawal changes only active local
resolution.

This is deliberately a single-observer recovery calibration. It does not yet
model contrary evidence, cross-domain collusion, authority weighting, or gradual
capability restoration, so it should not be generalized into a false-positive
rate for production systems.

## Architecture ablations

| Removed control | Deterministic consequence |
| --- | --- |
| Cross-domain dissemination | B-002 CBR rises from 0 to 2. |
| Observer scope | An out-of-scope observation changes from `scope_violation` to `accepted`. |
| Expiration | A stale observation changes from `expired` to `accepted`. |
| Trust-domain diversity | Same-domain Sybil reports change the result from `constrained` to `quarantined`. |
| Capability-specific response | A high-risk signal changes from `constrained` to `quarantined`. |
| Local sovereignty | TCX resolves at each receiver; `central_equal` broadcasts one central envelope. |

These are causal control experiments, not supported deployment profiles. The
conforming reference configuration keeps every listed control enabled.

## Status and next research boundary

The deterministic milestone is complete and reproducible. The next step should
remain deterministic until the central monitor has a faultable implementation,
heterogeneous local policies are represented, and the false-containment suite
includes contrary evidence, collusion, and restoration gradients. Only then is
an AgentDojo or live-transport integration warranted.
