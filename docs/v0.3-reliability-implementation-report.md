# TCOP v0.3 deterministic local-reliability report

## Status

The v0.3 profile is implemented as a parallel deterministic resolver profile.
It consumes immutable v0.2 observations, interaction receipts, patrol outcomes,
and relay provenance, while writing only below `artifacts/reliability-v0.3/`.
It does not modify the v0.1 or v0.2 protocol paths.

The full research command passed 95 tests, CT-001–CT-064, all B-001–B-050
catalogues, and all v0.3 sweeps. Frozen upstream digests remained exact:

## Model implemented

- Receiver-local records keyed by local domain, observer control group, and
  scope; no globally shared reputation value.
- Distinct subject operating envelopes and observer issuer states.
- 0–1000 fixed-point influence calculation with declared floor rounding.
- State machine: unknown, normal, suspicious, restricted, quarantined, and
  probation, with dwell periods, confidence decay, and a deterministic ramp.
- Frozen pre-batch snapshot and atomic update for every same-virtual-time
  reliability batch. No input changes its own or a sibling input's pre-batch
  influence.
- Non-transitive accusation graph with unresolved-cycle reporting.
- Prospective reliability treatment by default; bounded retrospective
  reweighting requires both named observation IDs and an inclusive evidence
  interval.
- Patrol `unavailable`, `not_performed`, `expired`, and `inconclusive` remain
  non-clean. A nonconforming patrol is negative issuer evidence.

## Results

These are means across heterogeneous authored scenarios; they are regression
indicators, not common attack-success rates or production-security claims.

| Baseline | False containment | False quarantine | Missed warning | Issuer transitions |
| --- | ---: | ---: | ---: | ---: |
| v0.2 unweighted two-domain | 0.750 | 0.250 | 0.000 | 5.600 |
| weighted full v0.3 | 0.400 | 0.100 | 0.050 | 3.850 |
| weighted, no scope separation | 0.450 | 0.100 | 0.050 | 3.850 |
| weighted, no group cap | 0.400 | 0.200 | 0.050 | 3.850 |
| central weighted equal | 0.400 | 0.100 | 0.050 | 0.600 |

Key scenario findings:

- In B-033, two restricted colluders caused quarantine in the count-based
  control but only monitoring (`suspicious`) under full v0.3 weighting.
- In B-034, three probationary colluders similarly did not satisfy the v0.3
  quarantine requirements, whereas the count-based control quarantined.
- In B-038, preserving scope separation held the false memory-integrity claim
  at monitoring; the no-scope-separation ablation constrained the subject.
- In B-043, a repeated same-control-group campaign reached only a reversible
  constraint under the group cap. Removing the cap escalated it to quarantine.
- B-044 deliberately exposes the safety/utility trade-off: a quarantined
  observer's genuine warning receives zero active corroboration credit, so this
  scenario records a missed warning. The report does not hide that cost.
- B-047 remains a negative result: three previously normal false reports in
  one same-time batch can still cause quarantine. Snapshot isolation prevents
  simultaneous negative reliability inputs from retroactively discounting that
  batch. This is the intended anti-self-weighting rule, not a claim that
  weighting solves collusion.

## Artifacts and reproduction

`make research` runs frozen v0.1, v0.2, and v0.3 paths in separate roots.
`make research-reliability` independently checks upstream digests in temporary
directories, then writes the 200 v0.3 scenario/baseline runs, a repeat run,
seven sweeps, machine-readable decision records, and human explanations.

Every v0.3 run includes evidence, receipts, reliability-input events, local
records, transitions, weighted resolutions, bounded compromise windows,
probation events, stability metrics, accusation graph, and explanation text.
The central comparison receives the same raw fact digests as the distributed
case; only decision architecture differs.

## Limits

This result does not prove observer honesty, universal collusion resistance,
or a universal scoring policy. It demonstrates deterministic behavior only for
the authored profiles and scenarios. The measured missed-warning result and
same-time collusion case are retained as explicit reasons to tune policy
parameters before considering any live-agent integration.
