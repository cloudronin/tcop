# TCOP v0.3 deterministic reliability-profile decisions

1. v0.3 is a parallel resolver profile. It consumes validated immutable v0.2
   observations, receipts, patrol results, and relay provenance without
   changing v0.1 or v0.2 schemas, scenarios, code paths, or artifact roots.
2. Reliability is a receiver-local record keyed by local domain, observer
   control group, and normalized scope. It is not a portable global score.
3. Subject operational risk and observer issuer reliability are distinct state
   dimensions. A reliability update never rewrites the signed observation.
4. Same-virtual-time reliability inputs are evaluated against one frozen
   pre-batch ledger snapshot and committed atomically after all evaluation.
   No input can alter its own or a sibling input's pre-batch weight.
5. Reliability does not propagate transitively between control groups.
   Unsupported accusations are retained in the accusation graph but create no
   reliability update.
6. The reference profile uses integer factors on 0–1000 and left-to-right
   floor rounding. Its dynamic reliability factor and issuer-state factor are
   explicit, separately recorded components.
7. A valid signature proves origin only. Scope authority, receipt quality,
   freshness, local reliability, issuer state, and group independence remain
   local resolver inputs. Quarantined issuers provide zero active credit.
8. Relays retain the original observation identity and cannot add a control
   group, raise reliability, or create corroborative influence.
9. Reliability changes are prospective by default. An old observation keeps
   its first local weighting projection. Retrospective discount needs both an
   explicit observation ID and an inclusive explicitly evidenced compromise
   interval; immutable history is never erased.
10. Patrol outcomes use the same issuer model. `unavailable`, `not_performed`,
    `expired`, and `inconclusive` are not clean results. A nonconforming patrol
    is auditable negative evidence even if its subject finding was correct.
11. The central comparison receives the exact raw observation, receipt, patrol,
    enforcement-adapter, and fault inputs. Only the locus of its reliability
    ledger and decision differs from distributed TCX.
12. All v0.3 outputs remain below `artifacts/reliability-v0.3/`. `make
    research-reliability` checks frozen upstream digests in temporary roots.
